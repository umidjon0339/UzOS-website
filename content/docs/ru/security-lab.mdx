# Лаборатория безопасности

В UzOS есть **70 атак**, и у каждой — своя **защита**, которая её останавливает. Можно прочитать об атаке, безопасно её смоделировать, запустить по-настоящему и увидеть в журнале аудита, как защита её отклонила.

## Команда seclab

```
seclab list                  все атаки и их защиты
seclab info <атака>          что она делает и что её останавливает
seclab attack <id>           моделирование: только чтение, всегда безопасно
seclab attack <id> live      запустить по-настоящему (мало и ограниченно, только root)
seclab defence <id>          показать защиту
seclab verify <id> | all     самопроверки защит
seclab log                   последние отказы, новые сверху
seclab status                счётчики, watchdog, свободные слоты процессов
seclab repair                заставить каждую атаку убрать за собой (только root)
```

## Попробуйте: fork-бомба

*Fork-бомба* создаёт процессы в цикле, пока слоты не закончатся у всех. Её защита, `slot_quota`, ограничивает число процессов одного пользователя.

```
seclab info fork_bomb        прочитать о ней
seclab attack fork_bomb      смоделировать (ничего на самом деле не происходит)
seclab attack fork_bomb live запустить по-настоящему от root
audit                        посмотреть, что отклонила slot_quota
seclab status                таблица процессов по-прежнему работает
```

Живой запуск помечается как **BLOCKED**, если атаку отклонила её собственная защита. Это доказывает, что именно эта защита работает.

## Ещё одна: правка ядра

`kernel_patch` записывает один байт в код ядра. Защита `integrity_check` хранит SHA-256 ядра с момента загрузки, а `exec` отказывается запускать программы на изменённом ядре.

```
integrity                    то же ли это ядро, что загрузилось?
seclab info kernel_patch
```

## Как устроена защита

- **Capabilities**: власть root разделена на именованные привилегии, например `CAP_KILL`, `CAP_SETUID` и `CAP_SECLAB`. Каждая проверка запрашивает ровно одну. Попробуйте `caps` и `caps guest`.
- **Журнал аудита**: каждый отказ записывается со временем, пользователем и PID. Очистить его не может никто. Попробуйте `audit` и `audit sum`.
- **Целостность ядра**: хеш SHA-256 кода и констант ядра, измеренный при загрузке.

<Callout type="note">
Живые атаки небольшие и ограниченные, а `seclab repair` отменяет их последствия. Некоторые атаки, которые 32-битная виртуальная машина не может выполнить по-настоящему, показаны как честные иллюстрации.
</Callout>

В папке каждой атаки, например `modules/process_management/security/fork_bomb/`, есть `README.md` с описанием реальной атаки и защиты.
